---
title: "Accept ACH Payments with Kicbac Hosted Bank Fields"
sidebarTitle: "ACH"
description: "Collect ACH bank details using Kicbac hosted fields, tokenize the account without exposing raw routing numbers, and charge the ACH token server-side."
---

Kicbac hosted fields handle ACH account collection entirely in the browser, so raw routing and account numbers never touch your server. The fields tokenize the entry and return a short-lived `paymentToken` you pass to your backend for the charge.

## Hosted ACH fields

```ts ach-fields.ts
import { loadKicbac } from "@kicbac/js";

const kicbac = await loadKicbac(import.meta.env.VITE_KICBAC_TOKENIZATION_KEY);
if (!kicbac) {
  throw new Error("Kicbac.js is only available in the browser.");
}

const session = kicbac.createFieldSession({
  fields: {
    checkname: { selector: "#check-name", placeholder: "Jane Doe" },
    checkaba: { selector: "#routing-number", placeholder: "490000018" },
    checkaccount: { selector: "#account-number", placeholder: "24413815" }
  },
  onReady: () => console.log("ACH fields ready"),
  onChange: (_fields, isValid) => console.log({ isValid })
});

const response = await session.tokenize();
await fetch("/api/ach", {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({ token: response.token })
});
```

## Server charge

```ts ach-charge.ts
import Kicbac from "kicbac";

const kicbac = new Kicbac();
const orderId = `ach_${crypto.randomUUID()}`;

const result = await kicbac.transactions.sale({
  amount: "19.99",
  paymentToken: "11111111-111111-111111-111111111111",
  orderId
});
```

Persist the server-generated `orderId` before the call. A new attempt after a
definitive decline needs a fresh ID and payment token. If the outcome is
ambiguous, do not resubmit; query and reconcile the existing ID first. The ID
is a correlation key, not an idempotency guarantee.

<Note>
  The token `11111111-111111-111111-111111111111` is the ACH test token. Use it in test mode only — never in production.
</Note>
