Kicbac SDKs separate customer declines from exceptional failures. A `response=2` decline returns a typed result object (`result.ok === false`) — it is not thrown. Most `response=3` gateway errors are thrown as `GatewayError`; `response_code=301` is the rate-limit case and is thrown as `RateLimitError`. The Node SDK also reports connection failures, timeouts, and parse failures as `ConnectionError`, `TimeoutError`, and `ParseError`. Handle each path explicitly.

Python exceptions include `APIError` for gateway/transport failures,
`APIStatusError` for unexpected non-200 HTTP statuses, and
`APITimeoutError` for request timeouts.

## Node

```ts errors.ts
import Kicbac, {
  ConnectionError,
  GatewayError,
  ParseError,
  RateLimitError,
  TimeoutError
} from "kicbac";

const kicbac = new Kicbac();

try {
  const result = await kicbac.transactions.sale({
    amount: "0.99",
    paymentToken: "00000000-000000-000000-000000000000"
  });

  if (!result.ok) {
    console.log("declined", result.code, result.message);
    return;
  }

  console.log("approved", result.transactionId);
} catch (error) {
  if (error instanceof RateLimitError) {
    console.error("rate limited", error.httpStatus, error.responseCode);
  } else if (error instanceof GatewayError) {
    console.error("gateway error", error.responseCode);
  } else if (error instanceof TimeoutError) {
    console.error("request timed out", error.timeoutMs);
  } else if (error instanceof ConnectionError) {
    console.error("connection failed", error.sent);
  } else if (error instanceof ParseError) {
    console.error("gateway response could not be parsed");
  }
  throw error;
}
```

## Python

```python errors.py
from kicbac import Kicbac
from kicbac.errors import APIError, APITimeoutError

client = Kicbac()

try:
    result = client.transactions.sale(
        amount="0.99",
        payment_token="00000000-000000-000000-000000000000",
    )
    if not result.ok:
        print("declined", result.response_code, result.message)
    else:
        print("approved", result.transaction_id)
except APITimeoutError:
    print("timeout before a response was parsed")
    raise
except APIError as error:
    print("gateway error", error.response_code)
    raise
```

## Retry policy

- `query.php` calls may be retried by SDK policy.
- `transact.php` POSTs are not retried after the request may have reached the gateway.
- A pre-send connection failure can be retried because no gateway operation was created.
- Use `dup_seconds` for gateway duplicate detection, not client-side blind retries.

## Reconcile an ambiguous write

Persist a unique server-generated `orderId` before calling `transact.php`.
When a timeout, broken connection, or unreadable response may have happened
after the request was sent, keep that payment attempt blocked and query the
same ID:

<CodeGroup>
```ts Node.js
const matches = [];
for await (const transaction of kicbac.query.transactions({ orderId })) {
  matches.push(transaction);
}

if (matches.length > 0) {
  await reconcileAttemptFromGateway(matches);
} else {
  await keepAttemptBlockedAndRecheckLater(orderId);
}
```

```python Python
matches = list(client.query.transactions(order_id=order_id))

if matches:
    reconcile_attempt_from_gateway(matches)
else:
    keep_attempt_blocked_and_recheck_later(order_id)
```
</CodeGroup>

An empty query immediately after the error does **not** prove the write failed.
Wait for a webhook, query again after a delay, or send the attempt to manual
review. Create a new attempt only after the original outcome is definitive.
Enforce at most one processing or unconfirmed attempt for each customer account
and payment operation; browser storage can improve the UX but cannot enforce
that server-side invariant.
