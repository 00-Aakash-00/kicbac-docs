Kicbac.js injects secure iframe fields directly into your page for card and ACH details, then returns a single-use `payment_token` your server can charge. In the supported hosted-field flow, card and bank data stays outside your application. The `@kicbac/js` and `@kicbac/react` packages provide the field and session APIs — use this page if you are integrating with vanilla JavaScript or need low-level control.

## Tokenization session

Pass your public tokenization key to `loadKicbac()`. It returns `null` only during server-side rendering, and rejects if the key is missing, so always provide the key explicitly.

```ts
import { loadKicbac } from "@kicbac/js";

const kicbac = await loadKicbac(import.meta.env.VITE_KICBAC_TOKENIZATION_KEY);
if (!kicbac) {
  // Server-side render: hosted fields only run in the browser.
  throw new Error("Kicbac.js is only available in the browser.");
}

const session = kicbac.createFieldSession({
  fields: {
    ccnumber: { selector: "#cc-number" },
    ccexp: { selector: "#cc-exp" },
    cvv: { selector: "#cc-cvv", display: "required" }
  }
});

const response = await session.tokenize();
console.log(response.token); // send this payment_token to your server
```

Tokens are single-use and expire after 24 hours. Kicbac.js uses one page-wide hosted-field session — destroy a session before mounting another one.
